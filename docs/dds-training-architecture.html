The conventional approach asks a large model to figure everything out from a raw question. Khanary constructs much more of the problem first, then delivers a prepared reasoning environment to DDS — not a naked question.

Conventional Q → [MODEL: figure everything out] → A Khanary Q → AIML(Q) ⊕ NARY(Q) structural + associative embedding → F_Q bounded active field → Query(F_Q, P) → E_Q graph interrogation → Yax / µ → XCFE routing + reasoning ops → JROM_projection structured machine thought → [DDS: decode + compose] → Reply
Key identity: Knowledge ≠ Weights. Knowledge is distributed across G_semantic + Books + AIML + Grams + IDB + Confidence + µ. DDS supplies the compressed numerical model state necessary for language composition and generalization.

§2 — The Training Boundary

Core Invariant DDS does not train on the problem Khanary receives. DDS trains on the problem Khanary produces.

The training pair is:

X_DDS  =  P( F_Q, E_Q, X_XCFE, µ )      ← Khanary's prepared projection
Y_DDS  =  desired linguistic completion    ← target artifact

Not:

Q_raw → A     ← this trains the model to re-derive structure Khanary already supplies

Training on raw Q→A pairs teaches the model to discover structure that Khanary has already resolved deterministically. Those parameters are wasted — they duplicate symbolic work and prevent the neural substrate from shrinking.

Loss function ℒ = − Σ_t log p_θ( y_t | y_<t, P(F_Q, E_Q, X_XCFE) )

The gradient applies only to the projection → target mapping. Provenance (how Khanary arrived at the projection) is outside ∇θ.

§3 — XShard Format

A training shard is not a conversation record. It is a Khanary cognition record with a hard boundary between what is stored for audit and what crosses the gradient boundary.

Shard identity XShard_i = ⟨ Prov_i, Projection_i^ABI, Target_i, Metrics_i ⟩ Prov_i = JROM( CycleID_i ) Projection_i = RequestRouter( CycleID_i ) Target_i = MCPReply( CycleID_i )

The JROM window is sealed by cycle identity, not by MCP return time. Concurrent requests with different CycleIDs can never contaminate the same shard.

The provenance block can be stored, replayed, audited, and used to reproduce P_K(Q), but it must not leak across the neural training boundary. Otherwise DDS learns Q→F_Q, while Khanary already computes Q→F_Q — wasting parameters duplicating symbolic cognition.

JROM: Trace vs Projection

The JROM has two distinct views:

ViewContentsGradient boundary
JROM_traceComplete execution log — timestamps, internal scoring, diagnostics, all tool eventsOutside ∇θ
JROM_projectionSelected machine-thinking state intentionally presented to DDSInside ∇θ
 
JROM_trace  →  project( trace, ABI_version, target )  →  JROM_projection  →  DDS

The project() function is a versioned, deterministic Khanary-side view over the trace. Changing the projection view definition changes the ABI — it is not a preprocessing step.

Revised training invariant RAW EXECUTION PROVENANCE IS NOT TRAINING INPUT. PROJECTED JROM THOUGHT IS.

The Model as Decoder

JROM_projection is the machine's thought product. The weights are the projection/translation engine that turns that machine representation into the requested human artifact:

Khanary thinks  →  JROM records the thought  →  Model expresses it

The projection target determines the output modality:

ProjectionTargetOutput
CHATnatural-language conversational response
CODEsource files, functions, implementations
PATCHdiff consistent with existing codebase
JSONstructured data object
K'UHULglyph grammar compliant bracket program
REPOmulti-file repository response

Same Khanary cognitive cycle, different decoder target. The symbolic reasoning substrate does not change per target — only the projection rendering changes.

§4 — Projection ABI

The reasoning_projection field is the interface contract between symbolic Khanary and neural DDS. It is not merely a formatting choice — it is a versioned ABI:

ABI identity ABI_{K→DDS} = P( F_Q, E_Q, X_XCFE, µ )

The projection vocabulary lives in the manifest — making it simultaneously the dictionary, ABI registry, and bootstrap teaching source:

{
  "⟁PROJECTION_ABI": [
    "version:v1",
    "⟁FIELD",
    "⟁EVIDENCE",
    "⟁INFER",
    "⟁COUNTEREXAMPLE",
    "⟁VERIFY",
    "⟁XUL"
  ],
  "⟁INFER":          ["meaning:determine what follows from supplied evidence"],
  "⟁COUNTEREXAMPLE": ["meaning:test the proposed inference against an alternative case"],
  "⟁VERIFY":         ["meaning:check the resulting claim against supplied evidence"]
}

One manifest declaration has three simultaneous readings:

ReadingUse
Training annotationThe meaning: value is the NL expansion for bootstrap stage 2
ABI version"version:v1" is a manifest key — bump it when the contract changes
Test oracleA model that knows the contract resolves ⟁INFER correctly; divergence signals C_ABI failure
ABI stability property Khanary implementation ≠ DDS interface Changing AIML patterns, gram routing, graph algorithms, or Micronaut selection does not require retraining DDS — provided the projection ABI version is unchanged.

Bootstrap Curriculum — Three Projection Stages

A single Khanary cycle can emit all three shard variants by rendering the projection differently. Graph queries, AIML activations, and XCFE trace are computed once; only the serialization of the projection changes.

StageModereasoning_projection format
1 NL Full natural-language rendering of F_Q + E_Q + XCFE. Works with any pretrained base.
2 MIXED NL + inline glyph + manifest annotation. Establishes equivalence: ⟁INFER meaning:determine what follows…
3 GLYPH Glyph sequence only. Compact. Requires ABI contract to be established from stage 2.

Once DDS has learned the projection ABI, the expensive expansion disappears from neural input — but Khanary retains Book(⟁INFER) for validation, inspection, versioning, and training. This is semantic compression across the neural boundary.

§5 — Gyroscope (Weight Alignment)

The gyroscope maintains a reference orientation: what DDS should produce given a well-formed projection. It detects drift when weights start learning to bypass the ABI — for example, re-deriving F_Q from patterns in the projection text rather than decoding the prepared structure.

Gyroscope signal Ω_gyro = P_glyph(C) − P_NL(C)

The NL view acts as the inertial reference. The glyph view is the needle. When they diverge, the weights have precessed — they are no longer decoding the compact projection faithfully.

ObservationDiagnosis
Glyph performance ≈ NL performanceWeights aligned — ABI contract is held
Glyph degrades, NL stableABI acquisition failure — C_ABI
Both degrade togetherC_composition or C_knowledge — not ABI drift
Gyroscope identity Gyroscope = alignment Governor controls how much work the weights receive. Gyroscope controls whether the weights remain oriented to their contract.

Alignment check: periodically evaluate a held-out set of matched (glyph, NL, target) triples from the same cognitive cycle. If glyph fidelity drops below a threshold relative to NL, flag the weights for realignment before the ABI contract degrades silently.

Equivalence Regression Test

A well-aligned DDS should produce equivalent artifacts from equivalent projections, regardless of which representation was used:

ABI equivalence test P_NL(C) ≡ P_glyph(C) (same cognitive cycle, different rendering) therefore: D( M(P_NL(C)), M(P_glyph(C)) ) ≈ 0 Large divergence → DDS is not faithfully interpreting one ABI representation → C_ABI failure

Information-Flow Leakage Test

A stronger regression: verify that project() is fully filtering provenance. If two different Khanary engines produce the same projection, DDS output must be identical:

Leakage test K_A(Q) ≠ K_B(Q) (different Khanary internals — AIML-A vs AIML-B, Graph-A vs Graph-B) but: project(K_A(Q)) = project(K_B(Q)) = P therefore under deterministic decoding: M(P)_A = M(P)_B

The model cannot know which symbolic engine produced P, because that information was eliminated by project(). If outputs diverge, provenance has leaked through the training boundary — the invariant is violated.

The gyroscope keeps the weights calibrated at whatever thinking level the governor sets. In low-thinking mode, it prevents weights from drifting toward re-deriving structure Khanary already provides.

§6 — Governor (Cognitive Load Distribution)

The governor is the load control. It measures how much unresolved cognitive work remains after Khanary's symbolic pipeline completes, and sets the thinking level delegated to DDS accordingly.

Governor identity Governor = load Higher governor offload → more Khanary work → less DDS thinking required Lower governor offload → gaps present → more DDS thinking required

Thinking level is the user-facing abstraction. Governor and gyroscope are the mechanisms underneath:

LOW thinking
High Khanary symbolic resolution. DDS mostly decodes + projects. Small model sufficient.
MED thinking
Some unresolved structure. DDS composes + limited inference from latent knowledge.
HIGH thinking
Significant unresolved structure. DDS needs latent knowledge + inference + compose. Larger model.
DDS thinking levelKhanary roleDDS role
LOWHigh symbolic resolution — fully preparedDecode + project into target artifact
MEDIUMSome unresolved structureCompose + limited inference
HIGHSignificant unresolved structureLatent knowledge + inference + compose

LOW does not mean dumb

Low DDS thinking can correspond to an extremely sophisticated Khanary reasoning cycle:

AIML → NARY → F_Q → Graph → µ → XCFE → Ch'en

It is called LOW DDS THINKING because that work has already happened. A fully resolved difficult problem could legitimately produce:

governor:
  thinking: low
  concept_coverage: 1.0
  arc_coverage: 1.0
  unresolved: []

projection:
  target: patch
  abi: v1

DDS only has to express the solution — the reasoning is complete.

Thinking level definition ThinkingLevel = amount of unresolved cognitive work delegated to DDS Not: total intelligence expended on the query

G_Q — Governor Signal

The governor derives the thinking level from cycle metrics — it is not an arbitrary setting:

Governor formula G_Q = f( C_V, C_E, U, κ, verification ) C_V = concept coverage C_E = arc / relationship coverage U = unresolved node count κ = structural confidence verification = XCFE Ch'en signal

High G_Q (governor fully open, Khanary carrying max load) → low DDS thinking. Low G_Q (gaps present) → high DDS thinking. The unresolved list is the governor's state readout — it names exactly which gaps Khanary could not close and is delegating to DDS.

ThinkingLevel is Part of the Projection Contract

Thinking level is passed into project() — it becomes part of the ABI, not implicit context that DDS has to infer:

Projection signature (updated) P_i = project( JROM_i, ABI_v, Target, ThinkingLevel )

DDS still sees only P_i. The governor's internal computation (C_V, C_E, κ) is provenance — outside ∇θ. Only the resulting ThinkingLevel crosses the boundary as part of the projection.

Model Routing by Load

Thinking level and model size are not synonymous. A tiny model could handle constrained low-thinking projections:

PATCH  + LOW    →  tiny DDS
K'UHUL + LOW    →  tiny DDS
JSON   + LOW    →  tiny DDS

CHAT   + HIGH   →  larger DDS
CODE   + HIGH   →  larger DDS

Routing therefore becomes:

DDS routing formula DDS = Route( Target, ThinkingLevel, ABI, Capacity ) Not: BiggestAvailableModel

Same Khanary stack, same projection ABI, different decoder capacity depending on what the governor reports per cycle.

§7 — Three Diagnostic Failure Modes

Reducing DDS model size produces three diagnostically distinct failure types. Confusing them leads to wrong conclusions about what needs to grow.

ModeConditionExperimental signature
C_knowledge P_K(Q) is insufficient — required information absent from F_Q / E_Q Specific factual domains degrade; high graph-coverage tasks remain strong; prepared and raw both miss same facts; Δ_n narrows selectively
C_composition M_n(P_K(Q)) is insufficient — DDS cannot reliably integrate prepared field into language Coherence degrades across all domains uniformly; even fully supplied answers become malformed; Δ_n approaches floor globally
C_ABI DDS does not sufficiently understand Khanary's projection language Glyph-mode output degrades while NL-mode output stays stable; model parses projection structure but misinterprets semantic keys
Graph/field coverage must be recorded as an experimental variable. Without it, a missing Book can masquerade as a weak DDS.

Coverage Metrics

Two coverage dimensions — vertex coverage and arc coverage — are both required because having all the concept nodes does not mean Khanary knows how they are related:

Coverage identity Coverage(F_Q) = (C_V, C_E) C_V = |E_Q.nodes_resolved| / |F_Q.activated_concepts| ← concept coverage C_E = |E_Q.arcs_resolved| / |F_Q.required_relations| ← relationship coverage

A field might have C_V = 1.0 while the critical ORGANIC → LIFE arc is absent — giving high node coverage but a reasoning gap. Store both scalars plus the unresolved list, not just a single coverage number.

§8 — The Collapse Experiment

The testable hypothesis: keep the entire symbolic side fixed and vary only DDS capacity. Compare Khanary-conditioned output against raw-question output at the same model sizes.

K  =  AIML + NARY + µ + Graph + Yax + XCFE     (held constant)

K + M_20B    →  Score(M_20B | P_K(Q))  vs  Score(M_20B | Q)
K + M_7B     →  Score(M_7B  | P_K(Q))  vs  Score(M_7B  | Q)
K + M_3B     →  Score(M_3B  | P_K(Q))  vs  Score(M_3B  | Q)
K + M_1B     →  Score(M_1B  | P_K(Q))  vs  Score(M_1B  | Q)
K + M_small  →  Score(M_sm  | P_K(Q))  vs  Score(M_sm  | Q)

The interesting quantity is the gap:

Gap metric Δ_n = Score( M_n | P_K(Q) ) − Score( M_n | Q )

The hypothesis predicts Δ_n remains positive farther down the parameter scale under Khanary conditioning, because classification, routing, retrieval, graph interrogation, and reasoning operations have already happened outside the model.

Composition Floor by Projection Target

The composition floor is not uniform across output modalities. Different targets require different neural capabilities:

TargetNeural demandTolerance
CHATFluency, coherence, toneHigher — tolerates some imprecision
CODESyntactic precision, scope correctnessLower — structural errors are visible
PATCHDiff consistency with existing codeVery constrained — most decisions pre-made
K'UHULGlyph grammar complianceHighly constrained — close to template

A model that can no longer produce coherent CHAT may still produce valid PATCH output because the projection for a patch is highly constrained — the model is filling in less. C_composition is therefore a vector, not a scalar:

Composition floor vector C⃗_composition = ( C_chat, C_code, C_patch, C_kuhul, … )

Test at least two targets at each model size to separate these. If CODE collapses later than CHAT as the model shrinks, the model is doing less semantic work on the more constrained target — exactly what the architecture predicts.

Two Ultimate Failure Thresholds

C_knowledge threshold

Minimum capacity needed to supply missing latent knowledge that F_Q + E_Q did not cover. Determined by graph coverage gaps. If Khanary eventually supplies essentially all task-relevant knowledge, this threshold becomes negligible.

C_composition threshold

Minimum capacity needed to express prepared knowledge coherently as the target artifact. Determined by projection target modality. This is the floor that dominates when Khanary coverage is high.

Ideal end state DDS capacity ≈ semantic integration + language composition + generation Not: retrieval + classification + routing + memory + reasoning + generation

ABI Regression Test

If DDS has only learned JROM_projection → HumanArtifact, then swapping the Khanary symbolic engine (different AIML patterns, different graph, different micronauts) while producing an identical JROM_projection for the same query should produce identical DDS output.

If the output diverges, the model has learned something about raw provenance that leaked through the training boundary. This test can be automated: generate matched pairs (same projection, different Khanary internals) and measure output divergence as a regression metric.

§10 — Locked Invariants

These three control surfaces are distinct. None absorbs another's responsibility.

Three control surfaces Governor controls cognitive delegation — how much unresolved work reaches DDS Gyroscope controls neural alignment — whether weights remain oriented to their contract project() controls information exposure — what crosses the gradient boundary
ThinkingLevel definition (locked) ThinkingLevel = unresolved cognitive work delegated to DDS LOW thinking can represent a difficult problem where Khanary already completed extensive AIML / N-ary / graph / XCFE processing. DDS merely expresses the solution. HIGH thinking means the symbolic system is deliberately handing unresolved work to the weights. The difficulty of the original query is not the measure.
DDS definition (locked) DDS is the learned decoder of Khanary machine thought. It can perform additional reasoning when the governor requests it (HIGH thinking), but that is delegated work — not its default architectural responsibility.

The boundary is executable rather than conceptual:

Canonical pipeline Q → F_Q → E_Q → JROM_trace → Governor → project( trace, ABI, target, thinking ) → JROM_projection → Gyroscope → Route( target, thinking, ABI, capacity ) → DDS → HumanArtifact ∈ { CHAT, CODE, PATCH, JSON, K'UHUL, REPO, … } JROM_trace outside ∇θ (provenance, audit, replay) JROM_projection inside ∇θ (what DDS trains on) ThinkingLevel inside P_i (part of the ABI contract, not raw provenance)
