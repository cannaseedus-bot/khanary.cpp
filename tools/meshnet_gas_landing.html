Why this avoids the hosting trap

The landing page can be served by any static host. GAS handles user login and orchestration. KQL localizes the session into user_mesh_id tables in KHANARY.CPP.

Contribute a static API model

A peer can register with GAS, then send a static_api_model.contribute.v1 message. KQL stores it as provider/routing evidence, never as semantic authority. 

{
  "endpoint": "send",
  "type": "static_api_model.contribute.v1",
  "to": "broadcast",
  "data": { "...": "see example JSON" }
}
